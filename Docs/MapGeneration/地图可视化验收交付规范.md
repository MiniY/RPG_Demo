# 地图可视化验收交付规范

本规范是 RPG_Demo 的 **Map Visual Acceptance Delivery Contract**。适用于会改变正式游戏地图的布局、地形、生态 Population、碰撞和可达性、出生安全区、出口/传送门、换层、重建或小地图可见结果的任务。仅文档或不改变地图行为的内部整理，可只运行相关检查并说明无需重建 MVP 的理由。

## 每次交付的完成条件

1. 实现与资源检查完成；受影响的 EditMode/PlayMode 测试有 XML、日志、通过数、失败数和 Unity 进程退出状态。`MapGenerated` 与 `GameplayReady` 分开记录。
2. 用当前项目与 Unity 2022.3.62f3c1 生成完整的 Windows x64 Player 目录，保留 EXE、`*_Data`、`UnityPlayer.dll` 等依赖。实际启动该 Player，记录启动、主界面、新冒险与目标玩法的验证结果。BuildPipeline 成功本身不等于 MVP 可运行。
3. 地图地形类任务建议至少八组固定回归与新增随机 Seed，逐组保存全景及针对本轮改动的局部图；生态类任务至少三组，每组有出生 Game View、生态/对象分布和地图概览 PNG。记录所有尝试及失败，不得只挑漂亮 Seed。动态改动还需真实运行录屏或 GIF。原始截图与视频保留；辅助标注另存并标明来源。临时验收相机或运行时探针只在隔离验收路径使用，不改变正式场景配置。
4. 从当前请求、成功 Attempt 和已提交的运行时地图上下文记录实际 Seed、ProfileId、GenerationId、Monster/Destructible 数量和类型构成，以及截图、视频、测试状态。配置资产日志中的 `RequestedSeed` 不能单独用作样例标签。取不到的字段写 `NOT VERIFIED`。
5. 产出可离线双击打开的 `index.html`、机器可读 `manifest.json` 和简明交接说明。报告使用相对路径链接，分别标记 `PASS`、`FAIL`、`PARTIAL`、`NOT VERIFIED`，并提供问题记录位置。向用户给出 MVP、报告、截图、视频的绝对路径。

## 交付位置与隔离

每项任务使用 `Artifacts/MapAcceptance/<任务名-日期>/` 独立目录，包含 `MVP_Windows_x64/`、`Screenshots/`、`Videos/`、`Report/`、`TestResults/`。需要分享时可将完整 Player 目录压缩成 ZIP。不得覆盖或删除旧验收目录。此目录的构建与媒体文件由 `.gitignore` 排除；规范文档和自动化工具保留在源码中。

验收运行须与正式存档和音频偏好隔离。旧存档恢复测试仅使用复制的槽位，记录源/副本哈希。不要为了截图改正式生成配方、移除实体或伪造画面。对于展示场景使用的临时相机、探针、强制动画状态，报告必须说明其作用；真实运行帧可作为视觉证据，但不得把测试摆位称为玩家自然游玩或把渲染读回称为人工视觉 PASS。

同 Seed 前后对比只有在生成配置、地图尺寸、相机范围与比例一致时才成立。没有可比较的上一轮真实截图时，明确写“无严格前后对比”，不以不同 Seed 冒充对照。全景若是多帧拼接，必须同时保留原图并标明拼接。

## 完成门禁与人工审核

分别记录 `IMPLEMENTATION_PASS`、`MVP_BUILD_PASS`、`SCREENSHOT_PASS`、`REVIEW_PACKAGE_PASS`。四项都成立才写 `READY_FOR_USER_ACCEPTANCE`；用户审核前只写 `MANUAL_ACCEPTANCE_PENDING`，绝不写 `MANUAL_ACCEPTANCE_PASS`。若 Player 只能启动却无法确认移动或关键玩法，则构建验收标为 `PARTIAL` 并附具体日志；BuildPipeline 返回成功本身不足以通过。

V2 多层地形的截图至少覆盖 H0/H1/H2、岩壁接低地与接水面、楼梯、阴影、水沫、岸线内外角、装饰、角色在高地的效果。截图可证明外观；楼梯通行、悬崖阻挡与遮挡还需要独立运行或相应 PlayMode 证据。不能把测试相机把角色摆到高地当成走楼梯的证据。

## 流水线

实现与资源核对 → 受影响 Unity 测试 → Windows Player 构建及实际启动 → 多 Seed 运行时样例与元数据 → 动态表现录屏 → 离线报告 → 用户视觉验收。优先复用 `Assets/Editor/MapAcceptance/MapAcceptanceBuild.cs`、`Assets/Tests/MapGeneration/PlayMode/MapAcceptanceCapturePlayModeTests.cs` 与 `Tools/MapAcceptance/` 下的报告及视频工具。每步记录完成条件与失败原因；技术限制时保留已有有效产物，未取得的证据标记 `NOT VERIFIED` 或 `BLOCKED`，不代填为 PASS。

有关本轮 V2 的具体验收矩阵见 [随机地图V2自动化与人工验收.md](随机地图V2自动化与人工验收.md)。Monster 生态的测试和素材索引见 [Monster生态PlayMode人工验收指南.md](Monster生态PlayMode人工验收指南.md)。
