# 随机地图系统架构说明

## 一、架构目标

地图系统的核心原则是将 Logic Data（逻辑数据）、Generation Rule（生成规则）、Visual Rendering（视觉渲染）、Collision（碰撞）和 User Interface（用户界面）分离。地图规则不依赖 Tilemap（瓦片地图）反向推断，所有运行时消费者都读取同一份 `MapData（地图数据）`。

## 二、核心数据流

```text
MapGenerationSettings（地图生成配置）
    ↓
RandomMapGenerator（随机地图生成器）
    ↓
MapData（地图逻辑数据）
    ├── MapTilemapRenderer（地形瓦片地图渲染器）
    │       ├── 四个视觉地形层
    │       └── 一个隐藏地形碰撞层
    ├── MapSimpleDecorationGenerator（简单装饰生成器）
    │       ↓
    │   MapSimpleDecorationData（简单装饰数据）
    │       ↓
    │   MapSimpleDecorationRenderer（简单装饰渲染器）
    │       ├── 地表装饰层
    │       ├── 树冠装饰层
    │       └── 隐藏装饰碰撞层
    └── MapMinimapRasterizer（小地图栅格化器）
            ↓
        MapMinimapController（小地图控制器）
```

`MapGenerationController（地图生成控制器）` 负责协调上述对象，并通过 `MapGenerated（地图生成完成）` 与 `MapCleared（地图清空）` 事件通知小地图等观察者。

## 三、逻辑数据层

`MapCell（地图单元）` 保存 `MapTerrainType（地图地形类型）`。当前地形包括：

- `Grass（草地）`
- `DeepWater（深水）`
- `ShallowWater（浅水）`
- `Sand（自然沙地）`
- `Forest（森林地表）`
- `Mountain（山地）`
- `Path（道路）`

`MapData（地图数据）` 保存地图尺寸、地图原点、出生点、出口和全部地图单元。深水、浅水和山地不可行走；草地、森林地表、自然沙地和道路可行走。

## 四、地形生成流水线

`RandomMapGenerator（随机地图生成器）` 按固定顺序执行：

1. 校验地图配置与地形阈值。
2. 根据 `Seed（随机种子）` 创建确定性伪随机流。
3. 使用高度、湿度和温度三个 Perlin Noise Channel（柏林噪声通道）分类自然地形。
4. 使用 `MapTerrainRegionCleaner（地图地形区域清理器）` 清理过小的四方向连通区域。
5. 建立深水边界和出生保护区。
6. 从出生点向地图边缘生成至少两格宽的道路。
7. 使用 Flood Fill（洪水填充）移除出生点无法到达的孤立可行走区域。
8. 使用 `MapTerrainNestingEnforcer（地图地形嵌套约束器）` 建立水、沙、草、山过渡带。
9. 使用 `MapTerrainPassageWidthEnforcer（地图通路宽度约束器）` 修复单格和错位通路。
10. 再次建立地形过渡带，保证通路扩宽后的视觉拓扑正确。

最终地图必须满足：

```text
Water（水域） → Sand（沙岸） → Grass（草地过渡带） → Mountain（山地）
```

每一条相邻可行走连接还必须至少属于一个完整的 `2×2 Clearance（2×2 净空块）`，以适配现有玩家碰撞体。

## 五、渲染与碰撞

`MapTilemapRenderer（地图瓦片地图渲染器）` 批量写入：

- `GeneratedWaterBase（水体底层）`
- `GeneratedSandBase（沙地底层）`
- `GeneratedGrassOverlay（草地覆盖层）`
- `GeneratedElevation（高地层）`
- `GeneratedTerrainCollision（地形碰撞层）`

前三类地形过渡使用 `TerrainTopology（地形拓扑）` 计算 North、East、South、West（北、东、南、西）四方向 Bit Mask（位掩码），再从 16 种自动瓦片状态中选取表现资源。

碰撞层只写入无可见 Sprite（精灵图）的碰撞瓦片，并关闭 `TilemapRenderer（瓦片地图渲染器）`；`TilemapCollider2D（二维瓦片地图碰撞体）`、`CompositeCollider2D（二维复合碰撞体）` 和静态 `Rigidbody2D（二维刚体）` 继续负责物理阻挡。

## 六、简单装饰

`MapSimpleDecorationGenerator（简单装饰生成器）` 使用独立于地形的随机流生成树木、灌木和散落岩石。每一种装饰类别还有自己的派生随机流，因此调整灌木密度不会重排树木位置。

装饰放置遵守：

- 完整占地必须位于地图内和可行走自然地形上。
- 不允许占用道路、出生保护区或出口净空区。
- 使用 Chebyshev Distance（切比雪夫距离）控制装饰间距。
- 树木保留完整 `3×3 Footprint（3×3 占地）`。
- 树冠写入玩家上方，树干和灌木写入玩家下方。
- 树桩和散落岩石使用独立隐藏碰撞层。

## 七、小地图与战争迷雾

`MapMinimapRasterizer（小地图栅格化器）` 将逻辑地形直接转换为 `Color32[]（颜色像素数组）`，再由 `MapMinimapController（小地图控制器）` 写入 `Texture2D（二维纹理）` 和 `RawImage（原始图像界面）`。

`MapExplorationState（地图探索状态）` 使用一维布尔数组记录已探索单元。玩家进入新网格时，系统以圆形半径揭示周围单元并更新 Fog Texture（迷雾纹理）。出生点、出口和玩家位置使用独立界面标记。

## 八、程序集和测试边界

运行时代码位于 `RPG_Demo.MapGeneration（RPG Demo 地图生成程序集）`。编辑器测试位于 `RPG_Demo.MapGeneration.Tests（RPG Demo 地图生成测试程序集）`，并通过 `UNITY_INCLUDE_TESTS（包含测试代码条件）` 限制在测试环境中。

这一边界避免 `NUnit（单元测试框架）` 进入正式运行时代码，并允许地图逻辑在不加载完整主场景的情况下进行确定性测试。
