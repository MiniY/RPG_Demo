# RPG_Demo 开发问题与故障解决案例库

## 1. 使用方法

故障案例的面试价值不在“遇到过 Bug”，而在能说明：

```text
现象
→ 可复现条件
→ 假设
→ 观测证据
→ 根因
→ 最小修复
→ 回归验证
→ 防止复发
```

以下案例均区分当前已验证事实、历史记录和推断。使用 STAR 讲述前，应根据自己真实参与程度调整“我做了什么”。

## 2. 案例一：新冒险错误继承旧位置迷雾

### 现象

开始 New Run 后，新地图在玩家旧位置附近出现已探索区域。

### 初始风险判断

可能原因包括：

- 探索数组未清空；
- Seed/MapData 复用了旧对象；
- 小地图 Texture 未重建；
- 玩家出生前后事件时序错误；
- 旧 Generation 回调迟到。

### 关键观测

`【已验证事实】` 定向探针记录：

- `MapGenerated` 回调观察到玩家仍在旧位置 `(62,62)`；
- 本次正确出生位置是 `(32,32)`；
- 回调阶段已揭示 37 个单元格。

### 根因

地图事件发布时，小地图开始按玩家当前位置更新探索；但 canonical player 尚未完成本代出生。问题不是探索数组单纯没清空，而是 Completion Boundary（完成边界）定义过早。

### 修复方向

- 调整迷雾更新/事件时序，使其只在最终 spawn 后观察玩家；
- 以 GameplayReady 或更精确的生命周期阶段作为消费边界；
- 保留 Generation 校验，拒绝旧代状态。

### 验证

- 修复前定向测试：0/1。
- 修复后定向测试：1/1。
- TowerRun flow：4/4。

### 可迁移经验

事件名不是契约。必须定义事件发生时哪些不变量已成立。

## 3. 案例二：Unity `.meta` 损坏导致资源引用异常

### 历史节点

提交 `92f84e8` 修复 malformed meta。

### 机制

Unity 通过 `.meta` 中的 GUID 维护资源引用。场景/Prefab 序列化保存的是 GUID/FileID，而不是只看文件路径。

### 故障风险

- `.meta` 格式错误；
- 资源和 `.meta` 不成对移动；
- 冲突解决时生成两个 GUID；
- Git 忽略 `.meta`；
- 用文本替换误改导入设置。

### 正确处理

1. 确认资产文件和 `.meta` 的对应关系。
2. 搜索 GUID 的引用位置。
3. 避免让 Unity 为已有资产无意生成新 GUID。
4. 在编辑器重新导入并检查场景/Prefab 引用。
5. 用 Git diff 审查 meta 变化，不只看 C#。

### 面试边界

不能只说“删掉 Library 重新导入就好了”。如果 GUID 已改变，重建 Library 不会自动恢复正确引用。

## 4. 案例三：TowerRun EditMode 断言全过但进程挂起

### 现象

`【已验证事实】` 21/21 断言通过并生成结果 XML，但 Unity Runner 未自然退出，最后终止精确 PID，退出码 `-1`。

### 正确结论

- 可以说：测试断言均通过。
- 不可以说：测试命令成功退出或该套件完整健康。

### 可能调查方向

`【待确认】`

- 未释放的 Editor callback；
- 静态事件/对象生命周期；
- 测试结束后仍有异步工作；
- Unity batchmode 自身退出问题；
- 资源导入或窗口/测试框架状态。

### 调试计划

1. 单独运行每个 fixture，二分定位。
2. 检查日志最后一个 test finished 之后的消息。
3. 开启更详细 test runner 日志。
4. 检查 `TearDown`、静态订阅、临时目录与 `EditorApplication` 回调。
5. 比较同版本最小空项目。
6. 只在证据支持时归因。

### 经验

测试有三层成功：

1. 断言通过；
2. Runner 正确完成并输出结果；
3. 执行进程正确退出。

三者不能混用。

## 5. 案例四：黑洞表现不能用 `-nographics` 证明

### 问题

黑洞传送门依赖真实图形管线。Headless（无图形）模式即使脚本逻辑运行，也不能证明 Shader/RenderTexture 最终像素正确。

### 处理

在 D3D11、RTX 4060 Laptop GPU 上执行真实 GPU 测试，结果 1/1。

### 经验

测试环境必须与被验证机制匹配：

- 纯算法 → EditMode；
- 场景交互 → PlayMode；
- Shader/像素 → 真实 GPU；
- 持久化 → 跨进程；
- 视觉美感 → 人工截图/实机审查。

自动化类型选错，会得到“绿色但无意义”的测试。

## 6. 案例五：无焦点 Batchmode 下 Input System 行为

### 现象

PlayMode batchmode 运行时，窗口无焦点/后台运行会影响 Input System 相关流程。

### 处理

测试环境使用仅测试所需的后台/焦点配置，避免把交互式桌面前台假设带入 CI。

### 边界

不能通过修改产品默认输入语义来“让测试通过”。测试 seam（接缝）应明确隔离。

### 经验

环境依赖要成为测试前提：

- 焦点；
- Time Scale；
- 图形设备；
- persistentDataPath；
- 域重载；
- 分辨率；
- 输入更新模式。

## 7. 案例六：`Arial.ttf` 在 Unity 2022.3 中不可作为预期内置字体

### 现象

运行时 UI 构建/预览引用 `Arial.ttf` 出现无效问题。

### 修复

改用 `LegacyRuntime.ttf`。

### 经验

- 内置资源路径也是版本化 API。
- “以前 Unity 可用”不等于当前 LTS 可用。
- 运行时构建 UI 应对字体依赖有明确资源策略，避免隐式 fallback。

## 8. 案例七：新地图失败不能预先替换当前 Active 世界

### 问题

若生成前先清空 Tilemap、退役对象，再开始随机生成；一旦生成/放置失败，玩家留在空世界。

### 设计修复

- 候选 Map/Plan 保持 Pending；
- Commit 前不替换 Active；
- 可重试失败只影响候选；
- 成功 Commit 后才投影和切换；
- 通过 Authority 保证只有一个有效世界。

### 历史证据

- `5df3b40` 建立 Pending/Active 运行时上下文；
- `2bfd4e1` 引入集成生命周期与 Commit 边界；
- `392b973` 强化 RandomGenerated/LegacyStatic 运行模式，并加入重试预算耗尽时保持旧 Active Generation/Registry 的测试。

`e7aff9f` 的范围不同：它修改的是 `BaseDamageable` 对唯一活动 RandomGenerated authority 的选择，并覆盖失败再生成时奖励生命周期仍绑定当前 Generation；不能把它单独当作 Map Orchestrator 失败保留机制的实现提交。

这里的直接保证是 Commit 前旧 Active Map/Registry 未被替换。TowerRun 失败时 Coordinator 会持有操作 Gate，所以不能进一步声称玩家仍可自由操作旧场景。

### 可迁移经验

这是 `Make-before-break（先建后拆）`：先准备可用新版本，再替换旧版本。类似蓝绿部署、配置热更新和缓存重建。

## 9. 案例八：旧 Generation 奖励污染新地图

### 风险

对象池、协程或延迟事件可能让旧地图对象在切层后才生成奖励。

### 修复

- 当前世界有唯一 Generation；
- Damageable/Reward 记录所属 Generation；
- `GenerationScopedRewardLifetime` 在代切换时退休；
- 过期回调依据 GenerationId 被拒绝。

### 经验

只销毁旧根对象不一定够。异步任务和池化对象可能脱离原父节点继续存活，必须在数据层携带版本身份。

## 10. 案例九：交易失败导致跨系统不一致

### 典型错误实现

```text
扣金币并保存
→ 添加商品失败
→ 返回错误
```

结果：玩家损失金币。

### 当前策略

- 先只读 Evaluate；
- 捕获背包和库存；
- 全部应用到内存候选；
- 统一提交；
- 任一失败同时回滚。

### 验证重点

- 金币不足；
- 商品售罄；
- 背包数量上限；
- 保存失败；
- 快速连点；
- 重复 Product ID；
- 数量溢出。

部分边界仍需最新人工/全量验证，不能笼统说全部已覆盖。

## 11. 案例十：设置 UI “自动化通过”仍不能替代视觉验收

### 当前事实

未提交设置 UI v6（由 v4 继续收口）：

- 构建预览成功；
- 1024×576、1280×720、1920×1080 均有音频页、三槽页和覆盖弹窗截图；
- 6/6 定向流程回归，Unity exit 0。

### 仍待确认

- 用户主观视觉批准；
- 低于 1024×576 或更极端宽高比；
- 中文文本溢出；
- 键盘/鼠标导航细节；
- 音量变化的主观听感。

### 经验

UI 质量至少分四层：

1. 结构存在；
2. 交互可达；
3. 布局在目标分辨率正确；
4. 视觉层级、动效、可读性和风格获得人工认可。

## 12. 案例十一：历史文档与当前实现冲突

```text

```

### 经验
