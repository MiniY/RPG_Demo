## 极简深色二次优化（2026-10-14）

用户提供的外观设置截图是本轮首要视觉参考：取其近黑背景、清楚的黑白层级、灰色容器和少量紫色选中效果，没有复制设置页布局。先前查看器的深蓝画布、青绿高亮、11px 节点名及密集边框让眼睛分散，也让“紫色待验证”与新紫色交互焦点相冲突。[旧界面实拍](viewer-before-minimal-20261014.png)与[最终总览](viewer-minimal-overview-20261014.png)可直接比较。

| 优先级 | 实际问题 | 这次怎么改 | 可检查的结果 |
|---|---|---|---|
| 高 | 选中对象与待验证状态可能混淆 | 紫色只给当前卡片、结果、连接和键盘焦点；待验证改为蓝灰空心点并写出状态 | `Torch_Blue` 详情、AA-01 和线条说明各自表达清楚 |
| 高 | 小字、过密卡片与右侧多层边框降低可读性 | 正文 14px、节点名 13px；右侧以标题和留白分组；路径等宽并可复制 | [Torch_Blue](viewer-minimal-torch-20261014.png)、[PlayerInventory](viewer-minimal-inventory-20261014.png) |
| 中 | 初次使用提示占据搜索空间，结果区与侧栏两层滚动 | 搜索靠前；3 步提示默认收起；结果和筛选共用侧栏滚动；提供直达流程与问题筛选按钮 | 搜索、清空、流程跳转与侧栏滚动实测 |
| 中 | 画布背景和连线色彩抢夺注意力 | 画布改近黑与极淡网格，普通线用中性灰，选中线紫色；保留箭头和不同证据线型 | 选中 `Visual` 边仍可读证据与方向 |

## 前一轮：有向图与视觉升级（2026-10-14，历史）

## 读者能看到的变化

| 原先 | 现在 | 怎样使用 |
|---|---|---|
| 相同的圆圈难辨脚本、Prefab、组件 | 卡片有 `CS`、`PF`、`GO`、`CP` 等类型标记和完整名称入口 | 先辨对象类型，再点卡片看完整路径与职责。 |
| 连线都是无箭头的直线 | 只对来源与目标语义明确的线画箭头；局部图左边是指向当前对象的线，右边是从它出发的线 | 点线，在右侧读“方向含义”“证据从哪里来”“验证到哪一步”。 |
| 多条线重合、点击困难 | 平行边错开，悬停显示短标签，选中后强化并弱化其他线 | 复杂处用右栏“看这条线的解释”进入同一证据。 |
| 业务链按钮写“第 N 步” | 改成“连接 N”，明确列表不代表运行时间线 | 按 A/B/C 筛选关系，再从源码方法逐段追踪。 |
| 旧运行证据在页面中缺少明白提示 | “旧运行证据不可沿用”单独翻译 | 仍需当前 Unity 测试或 Play Mode，不能把旧 XML 当新结果。 |

**白话解释**：这张图更容易帮你找到“谁连着谁、为什么连”；漂亮的箭头不会把一条线自动变成测试通过。

## 箭头的实际边界

- `Prefab → GameObject` 是包含；`GameObject → child GameObject` 是父子层级；`GameObject → Component` 是挂载。
- `Prefab Variant → Base Prefab` 是来源模板；Unity 序列化 GUID 关系表示文件中保存的引用。
- 人工核对的 `call`、`event`、`generation`、`data flow` 边沿图谱保存的来源指向目标，同时在详情中显示具体方法和证据。
- 有限 C# 文本名称匹配和系统间数量汇总保持无箭头。它们不能证明方法调用或运行先后。
- 箭头、线型和风险颜色分别表示记录方向、证据层级和问题关联；运行验证状态要读详情，不能靠颜色推断。
