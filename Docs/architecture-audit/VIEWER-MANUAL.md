# RPG_Demo 架构审计查看器使用说明

想边看边操作，请接着读 [零基础实操教程](VIEWER-TUTORIAL.md)。Obsidian 中可打开 [[RPG_Demo 架构审计查看器零基础实操教程]]。

> 给会一点 Unity、第一次打开这个页面的你。建议把本页和 `D:\UnityProjects\RPG_Demo\Docs\architecture-audit\viewer.html` 并排打开。本文的“区域 1～7”与页面上的编号相同。

## 先用 30 秒认识它

这个页面是一张**项目对象查找地图**：一张小卡片代表一个脚本、Prefab、场景对象、组件或资源；线代表扫描器发现的某种连接。它适合回答“我应该去哪里看代码和配置”“这个对象和谁有关”。页面也能打开证据位置，帮助你回 Unity 核对。

**白话解释**：把它当作“带线索的项目目录”。线索有强有弱；画出一条线，不等于游戏运行时一定沿这条线走，也不等于这里有 bug。

![2026-10-14 极简深色查看器区域 1～7](viewer-minimal-overview-20261014.png)

图中已经直接标出区域 1～7。左侧结果和筛选区可以滚动，截图只展示打开时的上半部分；下面的文字会把每一块说完整。

## 界面区域对照

### 区域 1：页头与统计——先确认你在看什么

你会看到页面名称、“可查对象”和“连接线索”的数量，以及**生成时**的来源分支、`HEAD` 简写、生成时间和当时源码是否有未提交修改。对象数包括脚本、Prefab、Scene、GameObject、Component 等，不是游戏里同时出现的物体数。连接线索数也不是实际执行次数。页头固定提示“当前是否仍一致：未检查”：离线页面不能实时读取此刻的项目文件；要核对请在项目根目录运行 `python Tools/ArchitectureAudit/scan.py --check`，main 的统一命令见 [自动更新维护说明](AUTO-UPDATE.md)。`HEAD` 是生成时的 Git 位置，不能单凭它断定当前图谱最新。

**什么时候用**：第一次打开时确认页面已加载；重建图谱后核对数量是否更新。

**常见误解**：不能用页头的连接数量推断同样多次运行调用，或推断所有连接已通过测试。

### 区域 2：左侧“找对象”——输入名称

在搜索框输入 `Torch_Blue`、`MonsterPlacementService` 或 `PlayerInventory`。页面会在下方列出匹配对象；点击一项，中央改为它的局部连接图，右侧显示详情。选中结果有紫色背景，方便你在同名对象中确认自己点了哪项。“试试”按钮会替你填入示例词，并把左侧滚回搜索与结果的开头。搜索同时看名称与文件路径，所以输入 `Monster` 可能得到很多结果。第一次使用时，点搜索框下的“第一次使用？展开 3 步”可展开或收起提示；完整练习入口就在这里。

**什么时候用**：你已经知道一个脚本、Prefab 或场景物体的名字时。

**常见误解**：结果太多时先增加完整名称，或在区域 4 选类型；搜索结果不是自动证明它在游戏中被调用。

### 区域 3：左侧结果列表——从名字进入对象

刚打开时这里不会把项目全部对象一次倒出来，而是提示你先输入名字或点系统卡片。开始查找后，结果上方会告诉你匹配数量，最多先显示前 120 项。每项展示类型、名称和路径；点中后右侧出现“它是什么、在哪里、与谁相连”。如果显示 0，页面会给出清空条件的按钮。

**常见误解**：搜索列表只显示前 120 项不代表其余对象丢失；改用更具体的名字或类型继续缩小。

### 区域 4：左侧“缩小范围”——只看关心的部分

- **业务链**：选 A 地图生成、B 战斗与奖励、C 背包与 UI。页面先清掉旧搜索和筛选，左侧出现“逐条查看流程连接”；点“连接 N”会打开它的来源对象。这里是一组已核对的关系，**排列不代表游戏执行顺序**；要确认真实先后，还须沿具体方法读源码。选好流程后，你仍可再加系统、类型或问题状态筛选。
- **快速找到筛选**：搜索框下的“按流程或问题编号找”会把左栏滚到区域 4，不会改动当前筛选。
- **定位问题**：选 `AA-01` 等编号，会清掉无关的搜索和筛选、打开对应的问题状态，并跳到关联对象；完整复现条件请点右侧的问题文件。
- **系统**：例如 `Monster`、`Inventory`。它按文件和职责把对象归组；在中央总览点一张系统卡片也会选这个系统。
- **更多筛选**：点开后才看到“类型”和“问题状态”，第一次使用可以先不动它们。类型例如 `prefab`、`script`、`component`。`Prefab（预制体）` 是可复用的对象模板；`GameObject（游戏对象）` 是场景或 Prefab 内的对象；`Component（组件）` 是挂在对象上的功能或数据。
- **问题状态**：在“更多筛选”内，只列与所选状态关联的对象。“还没验证”表示证据还不够，“已确认问题”有可复核的缺陷证据，“风险线索”值得检查，“设计关切”是可讨论的取舍；列表**没有**“一切正常”选项。

多个条件会同时生效，相当于“既要满足 A，又要满足 B”。“回到系统总览”只切换中央视图；“清空搜索和筛选”才会撤销所有条件。

**白话解释**：筛选像在文件夹里逐层缩小范围。筛到 0 条时，先清空一个条件，不要立刻判断对象不存在。

### 区域 5：中央连接图——先看系统，再看对象附近

刚打开时是**系统总览**：每张大卡片是一组对象。点 `Monster` 后，左侧会自动滚到该组结果；再点具体结果，中央才变成这个对象的**局部连接图**。中间是当前对象，左边是“谁指向它”，右边是“它指向谁”。每侧根据画布高度最多画 7 个相邻对象，右侧列表仍保留完整连接。长名称在卡片里可能省略；鼠标停留可看全名，右侧给完整文件路径。点系统卡片时会清掉先前的搜索和其他筛选，只保留刚选的系统。

顶部“全部 / 谁指向它 / 它指向谁”只改变**图上画出的方向**，不会删除右侧连接或修改 `graph.json`。`＋`、`－`、`还原视图` 只改变画面位置与大小，不改变数据。鼠标滚轮可缩放，拖动空白处可平移；点卡片看对象，点线看连接。`回到系统总览` 返回大结构，`清空搜索和筛选` 回到初始状态。

**白话解释**：系统卡片先告诉你项目有哪些区域；点具体对象后，只展示它左右最相关的一小组连接，避免把所有文件挤在一张图上。

### 区域 6：中央“线条怎么读”——先看证据，再判断

**箭头表示确定的记录方向，线型表示证据层级；紫色表示当前选中，蓝灰标记和琥珀标签分别提示待验证及问题关联。验证结论须读右侧文字和证据，不能只看颜色。**

| 你看到的线 | 说明 | 使用方式 |
|---|---|---|
| 实线 | 文件里的明确引用，或人工核对过的源码关系；其中有些另有 Unity 测试。 | 点击线条后看右侧的“验证到哪一步”。实线本身不等于运行通过。 |
| 虚线 | 只在 C# 文本里找到了名称。 | 当作“去这里查”的提示，不能直接称为方法调用。 |
| 点线 | 已找到具体源码位置，但当前运行时仍待验证，或旧测试与现有文件不再匹配。 | 可沿源码理解，再到 Unity 用测试或操作补证。 |

箭头从记录的来源指向目标，例如 `Torch_Blue.prefab → Visual` 表示“包含子对象”，`Torch_Purple.prefab → Torch_Blue.prefab` 的 `prefab source` 表示“变体继承来源”。已核对的调用、事件、生成、数据传递也各有对应方向。**仅 C# 名称匹配**和**系统总览汇总线**没有箭头：不能从这些线推断真实调用方向。箭头也不证明 Unity 已运行通过。鼠标停在线上会出现关系短标签；点线到右侧看具体含义。**紫色表示当前选中**；蓝灰空心点与“待验证”文字才表示运行证据不足；低饱和琥珀色标出问题关联。颜色不是“游戏已经坏了”的结论。

点击线条后在右侧读三件事：**这两个对象是谁 → 凭什么画线 → 验证到哪一步**。`静态文件连接` 只说明 Scene、Prefab 或源码有这项配置；`运行时核证` 还要有匹配的 Unity 测试或真实观察。页面提供的源码位置、测试 XML 只是核查入口，请阅读内容和适用条件。

**白话解释**：像侦探板上的线，先问“线从哪张照片、哪段代码来”，再问“现场真的发生过吗”。

### 区域 7：右侧“对象说明 / 连接说明”——决定下一步查什么

未选中时，这里提示你先点哪里。点**节点卡片或左侧结果**后，右侧按标题和间距展示：对象简介、来源位置、关联问题、指向它的对象（上游）、它指向的对象（下游）、改动时可能影响谁，以及下一步。“在项目哪里”有“复制路径”：成功会短暂显示“已复制”；若浏览器不允许剪贴板，路径会被选中，可按 `Ctrl+C`。点**线**，或点右侧列表中的“看这条线的解释”，右侧会改为连接说明：两端对象、关系类型、方向的白话解释、证据类型、验证状态、具体方法/数据（如有）、源码与测试入口。小窗口中右侧可独立向下滚动，不必缩小文字。

“上游”可以先理解为“哪些对象或文件指向它”；“下游”是“它指向谁”。这不是完整运行顺序。某项没有入边，不代表没人用它；动态生成、物理触发和反射可能未被静态扫描完整识别。

**常见误解**：右侧显示 `AA-01` 代表它与该问题有关，不能据此说这个对象本身已确认损坏。要看问题状态、触发条件和验证记录。

## 5～10 分钟上手路线

1. **第 1 分钟**：看区域 1 的数量解释，再看中央区域 5 的系统总览；先找 `Monster` 系统卡片。
2. **第 2～3 分钟**：点 `Monster`，再在左侧结果中找 `Torch_Blue.prefab`。看右侧“来源位置”，确认它是哪个文件。
3. **第 4～5 分钟**：在中央点与它相连的一条线，按区域 6 的顺序读线型、证据来源、验证状态。
4. **第 6～7 分钟**：试 A/B/C 中的一条业务链，点一条“连接 N”，再看右侧对象与上下游；不要把编号当作执行顺序。
5. **第 8～10 分钟**：点源码入口，回 Unity Project/Hierarchy/Inspector 核对对象和组件；看不清时点“回到系统总览”，条件太多时点“清空搜索和筛选”。

## 七个常用任务，照着点就行

### 1. 找 Monster Prefab

在区域 2 点“试试 Torch_Blue”，区域 3 找路径含 `Assets/Prefabs/Monsters/Torch/Torch_Blue.prefab` 且类型为 `prefab` 的项。点它，右侧记录完整路径，再在 Unity 的 Project 窗口定位同一文件。不要把同名 `GameObject`、`Component` 当成 Prefab 文件本身。

### 2. 看一个对象和谁有关

点左侧结果或中央卡片。右侧看“谁指向它”和“它指向谁”，再点“看这条线的解释”或另一个对象逐步走。中央每侧最多显示附近 7 个对象，小窗口会显示更少；完整列表以右侧为准。想暂时只看一侧，可点顶部方向按钮。

### 3. 看一条线是否可靠

点中央的线，或者在右侧连接列表点“看这条线的解释”。先看线型；再看右侧“证据从哪里来”和“验证到哪一步”。`C# 文本命中` 只能用来寻找代码；`源码核证`说明有人核对过指定代码；`运行时核证`才有当前输入对应的 Unity 测试记录。即使运行时核证，也只覆盖该测试的条件。

### 4. 查 AA-01 / AA-02

左侧“定位问题”选编号，右侧查看状态与源码；或者展开“更多筛选”，在“问题状态”选“还没验证”或“已确认问题”缩小列表。AA-01 目前仍有视觉验收缺口；AA-02 只在明确的多接收者条件下确认部分提交。看 [问题清单](ISSUES.md) 与 [验证记录](VALIDATION.md) 的完整条件，不要只看彩色边框。

### 5. 从系统总览走到具体对象

点“回到系统总览” → 点中央 `Monster` 系统卡片 → 左侧列表选 `Torch_Blue.prefab`。点系统卡片只是先选范围，不会自动替你认定哪个具体对象最重要。

### 6. 出现“0 个匹配对象”

先看搜索词是否过窄；再检查业务链、系统、类型和问题状态是否同时限制了结果。点“清空搜索和筛选”回到初始状态，或者点“试试 Torch_Blue”从一个已知名称重新开始。0 条仅表示**当前条件**下没有结果。

### 7. 与 Unity Editor 对照

右侧“打开来源”给出项目文件和行号：脚本到 IDE 看代码；Prefab 到 Unity Project 窗口打开并看 Inspector；GameObject/Component 要结合右侧文件路径，在对应 Scene/Prefab 的 Hierarchy 中查它的对象和组件。Scene 中的 Prefab override 需要看实际 Inspector 合成结果。Unity Play Mode 里再检查运行时引用、事件与行为；仅靠 HTML 页面不能替代这一步。

## 容易混淆的词，一句话解释

- `Node（节点）`：图上的一张卡片，代表一个可查的项目对象。
- `Edge（关系）`：两张卡片之间的一条线，记录“发现了什么连接”和证据来源。
- `Call Chain（调用链）`：方法实际调用的先后路径；**文本名称匹配不构成调用链**。
- `Serialized Reference（序列化引用）`：Unity 把 Inspector 里指定的对象引用写进 Scene/Prefab 文件；文件里有引用，还要检查它能否解析及运行时是否用到。
- `Confidence（置信度）`：这条连接有多少直接证据；不是出现 bug 的概率。
- `Validation（验证状态）`：目前确认到“文本线索、文件/源码位置、Unity 运行测试”的哪一步。

## 如果手册与页面不一致

以打开的 `viewer.html` 实际控件和当前 `graph.json` 为准。图谱会随脚本和资产变化而重建；数量、问题状态和 Unity 测试证据都可能更新。手册帮助你操作，不能替代 [VALIDATION.md](VALIDATION.md) 的证据边界。
